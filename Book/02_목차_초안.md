# 목차 초안 — Book-forge로 읽는 AI 에이전트와 Harness Engineering

**총 4개 파트, 17개 챕터 + 부록 4종.** 모든 챕터는 Book-forge(`818843d`) 또는 Agent-Evaluator(`d65889f`) 소스 코드를 직접 인용한다 — 가상의 예제 코드를 쓰지 않는다. 부록 A(용어집)는 코드 인용이 아니라 일반 개념 정의, 부록 B(업계 동향)는 이 책 유일하게 외부 자료를 인용하는 명시적 예외, 부록 C(프로젝트 아키텍처 지도)는 Book-forge 소스 전체의 참조용 지도, 부록 D(실전 체크리스트)는 3·8·9·10·13·16장에 흩어진 방법론을 Book-forge 이야기 없이 바로 적용 가능한 순서로 재조합한 것이다. 그 외 종합 정리 성격의 내용(에이전트 전체 인벤토리, Config 사용 현황, 품질 검증 축 통합)은 본문 챕터와 맺음말에 흡수돼 있다 — 본문과 부록을 오가며 같은 내용을 두 번 읽지 않도록, 각 개념이 처음(그리고 유일하게) 등장하는 자리에서 완결시켰다.

> - **4차 개편**: 독자 피드백("Agent·Book-forge·agent-evaluator 어느 하나도 명확히 이해되지 않는다", "각 에이전트가 보장해야 할 품질 수준과 예상/발생한 문제를 agent-evaluator가 어떻게 측정·처리하는지 이해하기 어렵다")을 반영해 8·9장을 다시 썼다. 이전 8장은 "Config 선택 패턴"을 3개 예시로만 설명했고, 9장은 Gate별로 조직됐지만 파이프라인 맥락과 분리돼 있었다 — 독자가 "이 에이전트 하나"에 대한 완결된 그림을 얻으려면 3장(실패 유형)·8장(Config)·9장(Gate)을 각각 열어 머릿속에서 합쳐야 했다. 새 8장은 파이프라인 실행 순서 그대로 16개 컴포넌트(LLM 에이전트 14 + 실시간 가드레일 2) 전부를 "무엇을 하는가·보장해야 할 품질·예상/실제 문제·측정·처리" 다섯 열 표로 완결시키고, 3장의 실패 유형을 태그로만 참조해 중복을 피했다. 새 9장은 같은 재료를 Gate 축으로 재편하되 각 Gate가 파이프라인 어느 단계에서 개입하는지를 명시했다. 맺음말의 "21개 컴포넌트 인벤토리" 표(8장과 사실상 같은 정보)는 삭제하고 8장 포인터로 대체했다.
